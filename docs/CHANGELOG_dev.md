## 階段 1：寫入 Lightroom 標籤（XMP）— 2026-10-27

### 你決定的兩件事
- 照片已經有星等或色標：**保留原本的，只補空的**（Lightroom 的 0 星視為沒有評等，會補上；-1 拒用會保留）
- JPG／PNG／TIFF：**不寫**，介面上說明原因

### 做了什麼
- 進階設定 →「輸出方式」新增「**寫入 Lightroom 標籤**」。選它時按鈕變成「② 寫入標籤」，表格「結果」欄顯示摘要（例如 `★★ 紅標 粉/藍 S03`），沒有 RAW 的照片顯示「（JPG 不寫入）」，狀態列說明原因。
- 命令列 `--output xmp`（搭配 `--preview`／`--apply`）。
- 寫入內容：

  | 項目 | 欄位 | 什麼時候寫 |
  |---|---|---|
  | 自動星等 1～3 | `xmp:Rating` | 「星等」功能開著，而且原本沒有星等 |
  | 代表張紅標 | `xmp:Label="Red"` | 「代表張」功能開著、是代表張，而且原本沒有色標 |
  | 膚色、整體、段落 | `lr:hierarchicalSubject` 的 `舞台色彩|膚色|粉` 等；`dc:subject` 放最末層的字（`粉`） | 一律寫 |
  | 人物、亮度 | 同上 | 對應功能開著時 |

- `.xmp` 已存在時用 XML 解析後合併，只動上表的欄位。重新寫入時先移除上次寫的「舞台色彩|…」，不會越寫越多；結果沒變時完全不重寫檔案。
- 紀錄檔 `_色彩分類紀錄_XMP_時間.csv`：每一筆**先記下原本內容（base64）與寫入前後的 SHA-256，再寫檔**；寫檔用暫存檔再換名，不會留下寫一半的 `.xmp`。
- 「↶ 復原上一次」認得 XMP 紀錄：新建的刪除、合併的逐位元組還原。**只處理內容還是本工具寫的樣子的檔案**；之後被 Lightroom 改過的不動，列在「沒有復原」清單。
- 和改名一樣：寫不了紀錄就一個都不寫；路徑必須在所選資料夾內；被竄改、指向資料夾外的紀錄會整批拒絕。
- 發布流程的小漏洞（`release.yml` 只改測試時不會觸發）**還沒修**：改 `.github/workflows/` 需要 GitHub 登入多一個 `workflow` 權限，目前的登入沒有，推送被拒絕。等你執行 `gh auth refresh -s workflow` 授權後再補上（只改一行，加 `tests/**`）。
- 新增 `tools/mutation_check.py`：在暫存複本裡故意把功能改壞，確認測試會失敗（之後的階段也能用）。

### 自己判斷的小決定（請過目）
1. **DNG 也不寫**：Lightroom 對 DNG 和 JPG 一樣，只讀檔案內嵌的 XMP、不讀旁邊的 `.xmp`，寫了也沒用。
2. **`dc:subject` 放最末層的字，`lr:hierarchicalSubject` 放完整路徑**：任務書表格寫兩個欄位都放 `舞台色彩|膚色|粉`，但 Lightroom 自己寫檔時是這樣分的；如果 `dc:subject` 也放完整路徑，Lightroom 會多出一堆名字裡有「|」的平面關鍵字。
3. **膚色和整體一律都寫**，不受「分類依據：只看膚色／只看整體」影響（那個選項是給檔名用的，關鍵字多寫一個不會造成困擾）。
4. **重新寫入時，星等和色標不會更新**：因為分不出是使用者設的還是上次本工具寫的，一律當成使用者的保留。想用新結果重寫，先按「↶ 復原上一次」再寫。
5. **格式會被正規化**：合併過的 `.xmp`，屬性順序（命名空間宣告移到前面）和屬性之間的換行縮排會改變，**所有值完全不變**（用 C14N 正規化比對驗證）。任務書要求「其他內容一個字都不能動」又要求「用正式 XML 解析、不要字串取代」，兩者無法同時做到逐位元組不變，我照「內容不變」處理。Lightroom 讀的是內容，不受影響。

### 還沒做／有風險的地方
- **沒有在 Lightroom 裡實際看過**。請照 `docs/Lightroom實機測試清單.md` 測一次。
- **色標顏色可能不對**：`xmp:Label` 存的是色標「名稱」。Lightroom 預設色標組英文版叫 `Red`，但中文版或自訂色標組的名稱可能不同，這時代表張會顯示成白色色標。清單 A-3 會確認；如果不對，下一步加一個「色標名稱」設定。
- **沒有用真實 ARW 測試**：這台電腦沒有 RAW 檔。端對端測試用真實 JPG 搭配假的 ARW（分析用 JPG、`.xmp` 寫給 ARW），和相機 RAW＋JPG 的情況相同；只有 ARW 的資料夾要靠 RAW 內嵌預覽分析，那部分沿用 v1.4 的程式，沒有改。
- 唯讀「資料夾」用模擬（紀錄檔寫不進去）測試；Windows 的資料夾唯讀屬性不會阻止新增檔案，沒有實際設定權限測。

## 追加需求（2026-10-27）：人數、點檔名開照片、校正工具、Lightroom 整合方案

### 做了什麼
1. **人數**：表格的「臉數」改名為「**人數**」並預設顯示；分析報告多一行「偵測到的人數：0人 23、1人 91…」；寫入 Lightroom 標籤時多一個關鍵字 `舞台色彩|人數|3人`（5 人以上合併成「5人以上」，篩選時才不會太碎），表格摘要也會顯示人數。CSV 欄位同樣改名為「人數」。
2. **點檔名開照片**：點表格的「原檔名」那一格，用 Windows 預設的看圖程式開啟；在任一列按兩下或按 Enter 也可以；按右鍵有「開啟照片」「在檔案總管中顯示」。照片已經改名或搬走時會提示重新分析。一秒內重複點同一張只開一次（避免點一下＋按兩下開三個視窗）。
   - 任務書原本規劃的「表格旁邊的縮圖預覽區」（階段 3）還沒做，這次先做你要的「直接開啟檔案」。
3. **校正工具（階段 2 的前半）**：
   - `tools/label_tool.py`：一張張看照片，用和檔名一樣的數字鍵標「膚色 → 整體 → 人數」，每張自動存到資料夾裡的 `labels.csv`，可以分好幾次標。預設隨機抽 150 張（固定亂數）。**不顯示程式的判斷**，避免影響你。已有不是標註格式的 `labels.csv` 時拒絕開始，不會蓋掉。
   - `tools/evaluate.py`：依 `labels.csv` 算膚色／整體／人數的準確率、混淆矩陣、錯最多的 20 張，存成 `tools/eval_報告_時間.md`。只分析有標註的照片（快）；`--half A|B` 把標註固定分成兩半（一半調參數、一半驗證）；`--from-csv` 可以直接用匯出的 CSV 計分。比對檔名時忽略顏色前綴，所以 `熱舞成發` 改過名的照片也對得上。
4. **基準分析**（只讀、預覽模式，結果存在暫存資料夾，沒有寫進照片資料夾）：

   | 資料夾 | 張數 | 時間 | 整體主色 | 膚色 |
